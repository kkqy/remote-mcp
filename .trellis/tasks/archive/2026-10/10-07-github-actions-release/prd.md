# GitHub Actions 自动编译发布

## 目标与价值
推送 `v*` 标签后自动验证、编译并发布正式 GitHub Release，用户可以直接下载对应平台的两个程序。

## 已确认事实
用户已同意创建任务，并选择 `v*` 标签正式发布。现有 check.yml 对 push/PR 执行 Linux、Windows 原生验证及四组合构建；build.sh 生成 Linux/Windows × amd64/arm64 的 remote-mcp、remote-mcp-transfer。GUI 仅支持 Windows。上一轮远端验证 37500084093 成功，不代表新发布链路已执行。

## 需求
- R1：普通分支与 PR 继续验证，仅 v* 标签 push 发布正式版本。
- R2：两个原生平台与四组合构建全部成功才发布；任何失败禁止发布。
- R3：四个包分别包含两个程序；Linux 为 tar.gz 并保留可执行权限，Windows 为 zip；文件名包含标签、系统、架构。
- R4：附带四个包及实际文件的 SHA256SUMS；使用 GITHUB_TOKEN，仅发布 job 拥有 contents: write。
- R5：全部附件上传成功后公开；已有 Release 不自动覆盖，失败有具体英文诊断；README 说明重复版本与失败草稿的恢复步骤。
- R6：README 说明下载、标签命令、产物与验证边界；文档/注释中文、运行提示英文；临时文件只在 .tmp/，保留无关 .opencode/package.json 修改。

## 验收条件
- AC1（R1/R2）：触发及 needs 检查证明普通分支/PR 不发布，验证失败禁止发布。
- AC2（R3/R4）：四组合真实构建打包；独立读取压缩包核对两个程序的字节、Linux 权限和四项哈希。
- AC3（R4/R5）：工作流语法、权限、失败行为及既有版本保护经检查；离线覆盖缺失产物、非法标签和发布命令失败路径。
- AC4（R6）：README 与入口一致，临时证据位于 .tmp/，无关修改不变。
- AC5：分别记录离线检查与远端实际结果；用户指定真实版本标签之前不创建版本。

## 范围外及延后
自动递增版本、main 预发布、macOS、安装包、签名、自动更新和软件仓库分发不在本次范围。Windows/arm64 原生和 Windows GUI 既有缺口不因发布构建通过而消除。实际发布实测等待用户指定版本号。
