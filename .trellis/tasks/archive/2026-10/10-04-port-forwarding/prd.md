# 新增 TCP 端口转发功能

## 目标与用户价值

让 Agent 通过运行 remote-mcp 的机器上的新监听端口，访问该机器的回环服务或其可达的内网服务。文档统一使用“运行 remote-mcp 的机器”和“运行 Agent 的机器”区分两端。

## 背景与证据

- 现有 Go 服务提供文件传输、命令执行及交互终端，无端口转发功能或前端（`README.zh-CN.md`、`internal/server/server.go`）。
- MCP 入口 `/mcp` 已支持可选 Token、TLS 和 Origin 校验，管理器统一注册工具并在服务关闭时清理（`internal/server/server.go`）。
- 运行资源跨 MCP 连接保持，以内存记录为主，重启不恢复（`.trellis/spec/backend/database-guidelines.md`）。
- 本次方向、TCP 范围、管理方式及正式方案均已获用户确认，并已批准实现。

## 需求

| 编号 | 已确认需求 |
| --- | --- |
| R1 | 仅转发 TCP 原始字节。监听位于运行 remote-mcp 的机器；目标为该机器回环地址或其可达的指定地址和端口，支持多条规则和并发连接。 |
| R2 | Agent 通过 MCP 创建、列出、查询和停止转发；创建返回资源 ID、实际监听地址及目标地址。 |
| R3 | 创建可指定监听 IP 和端口；省略 IP 沿用 MCP 服务监听 IP，省略端口或指定 0 时由系统分配。 |
| R4 | MCP 断连不停止转发。主动停止或服务正常退出时释放监听和现有连接；停止可重复调用；重启不恢复。 |
| R5 | 管理工具沿用 MCP 鉴权。TCP 数据原样传输，MCP Token 和入口 TLS 不自动保护转发端口，目标服务原有认证及 TLS 不变。 |
| R6 | 创建请求可幂等重试；资源、连接与记录有界；参数错误、端口占用及目标连接失败有明确可观察的结果，不泄漏流量内容。 |
| R7 | 沿用 Linux、macOS、Windows 支持范围，补充中文工具描述、使用说明及实际验证记录。 |

## 验收条件

- A1（R1）：通过真实 TCP 连接完成双向二进制传输，覆盖回环目标、可达非回环目标和并发连接；半关闭写端后仍能读完目标响应。
- A2（R2、R3）：MCP 能发现四个管理工具；创建后列表和查询反映相同资源，返回实际分配端口，指定端口按请求绑定；默认 IP 与服务配置一致。
- A3（R4）：MCP 断连重连后资源仍可访问；停止或正常退出后监听端口可重新绑定，现有连接终止；重复停止不会报资源仍在运行，重启无旧规则。
- A4（R5）：匿名模式可管理；启用 Token 后缺失或错误凭据无法管理，正确凭据可管理；普通 TCP 客户端无需 MCP 请求头即可访问转发端口，目标字节不被改写。
- A5（R6）：同一 request_id 和相同参数返回同一资源，不同参数冲突；无效地址、占用端口、连接失败、资源或连接超限均有可验证结果，失败后可继续创建或使用其他规则。
- A6（R6）：并发创建、停止、连接和服务退出通过竞态检查；记录清理不驱逐活跃规则的幂等记录；日志不包含流量内容或凭据。
- A7（R7）：完成本机测试、实际二进制转发闭环及六平台组合构建；真实内网环境或 Windows/macOS 原生运行若未执行，明确记为未验证。

## 范围外与使用边界

- 不支持 UDP、反向隧道、复用 MCP HTTP 端口传输流量、公网中转、转发规则持久化或断流恢复。
- 不新增本地辅助程序、前端、系统防火墙自动配置、应用层代理或证书终止。
- Agent 必须能连接新增监听端口；绑定全接口时使用可达的实际 IP 连接，不把 0.0.0.0 或 :: 当成远端访问地址。
- 普通转发不会改变目标服务的 HTTP Host、重定向或证书名称；目标应用自身的这些限制不由本功能自动处理。
