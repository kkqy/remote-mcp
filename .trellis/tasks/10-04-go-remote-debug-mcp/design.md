# Go 远程调试 MCP 服务技术设计

状态：完整方案已获用户批准；本次按用户最新要求改为可选 Token，产品行为及默认值以 prd.md 为准。

## 架构与交付边界

- 单个 Go 服务进程部署在客户机，通过内网或 VPN 接收 Agent 的 MCP 调用。
- 使用官方 Go SDK v1.8.0 的 Streamable HTTP，统一入口 `/mcp`；HTTP 鉴权与协议处理分层。首版协议兼容基线固定为 2025-11-25，通过 SupportedProtocolVersions 明确协商范围，不隐式承诺更新协议的全部行为。
- 服务内划分配置、MCP 工具注册、文件传输、进程管理、交互式终端和系统适配模块。
- 普通进程与终端会话使用应用级 ID 管理，不将生命周期绑定到单次 MCP 请求。
- Go 模块要求 Go 1.25.0 或以上，默认以 Go 1.27 工具链构建。系统与架构范围按 PRD 的评审方案执行，依赖证据见 research/transport-terminal.md。
- 当前以一个集成任务交付，文件、进程和终端共享鉴权及资源生命周期；按模块分步实现与验证，暂不拆分独立发布的子任务。

## 鉴权与部署

- 未设置或空 REMOTE_MCP_TOKEN 且未指定 --token-file 时允许匿名访问；非空 Token 配置后所有 MCP HTTP 请求仍须校验 Bearer Token。Token 从环境变量或权限受控文件读取；显式文件去除首尾空白后为空、不可读、权限或格式无效时失败，不退回匿名或环境凭据。非法非空环境 Token 也失败。普通运行日志不记录 Token。启动配置仅在启用鉴权时包含当前 Token。
- 允许访问的客户端共享服务运行账号的权限，不提供多租户隔离、不自动提权。
- 监听地址可配置，默认值见 PRD；部署文档明确内网或 VPN 地址的绑定方式。
- 支持配置 TLS 证书；加密 VPN 可承载 HTTP，普通内网部署建议配置 HTTPS。
- 按 MCP 规范验证请求 Origin；无 Origin 的非浏览器客户端可接入，有 Origin 时仅接受配置允许值。
- 启用鉴权时 SDK 的协议会话 ID 不替代 Token 校验。应用资源 ID 不授予额外权限。

## 启动时生成 MCP 配置

- 先校验配置并成功创建监听器，再获取实际端口、枚举网络接口及打印配置。失败时不输出看似可用的配置。
- 默认 IPv4 全接口监听对应所有处于启用状态的网卡上的可用 IPv4 地址，包含内网和 VPN 接口；不依赖网卡名称猜测或排除虚拟网卡。
- 单 IP 监听只生成该 IP 的配置。显式回环监听输出回环配置并标注仅本机可用。IPv6 监听按实际接收地址族生成 IPv6 配置，不能假设所有系统的 IPv6 监听都兼容 IPv4。
- 排除未指定地址、组播地址、停用接口、用于远端展示的回环地址及需要客户端作用域的 IPv6 链路本地地址；按规范化地址去重并稳定排序。同一网卡上的多个 IP 也分别生成。
- URL 使用实际协议、实际端口和 `/mcp`；IPv6 用标准 URL 构造函数处理方括号，不能手工拼接冒号。
- 每个地址分别输出一个完整 JSON 对象，顶层为 mcpServers，服务名统一为 remote-mcp，字段包括 type=http、url；仅启用鉴权时包含 headers.Authorization，匿名时完全省略 headers。各对象是备选配置，用户选择一个；不把多个 IP 默认注册为多个重复服务。
- 通过 JSON 编码器序列化并缩进，不用字符串模板插入 Token。启用鉴权时输出填入实际 Token，便于直接复制；示例文档只使用虚构占位符。不得同时将整份配置复制进结构化运行日志。
- 每段 JSON 输出到 stdout，中文地址说明、选择提示和普通日志输出到 stderr；多个独立 JSON 对象不宣称整体构成单个 JSON 文档。
- 枚举失败或没有匹配地址时明确说明，若监听已成功可继续运行；不能退回把 0.0.0.0 或 :: 当成 Agent 连接 URL。回环监听等无需网卡枚举的情况仍可生成确定配置。
- 地址只代表本机可监听的候选入口，不承诺网络可达；TLS 证书仍需覆盖选用 IP 或由用户配置匹配的域名，不自动关闭客户端证书校验。
- 常见 JSON 配置格式与客户端协议兼容性分开说明；其他配置格式的 Agent 使用相同 URL 和鉴权值转换，不声称所有客户端能直接导入该 JSON。

启用鉴权的示例（演示两个备选地址，端口和 Token 在实际启动时替换；匿名模式删除整个 headers 字段）：

```json
{
  "mcpServers": {
    "remote-mcp": {
      "type": "http",
      "url": "http://192.168.1.10:8080/mcp",
      "headers": { "Authorization": "Bearer <当前Token>" }
    }
  }
}
```

```json
{
  "mcpServers": {
    "remote-mcp": {
      "type": "http",
      "url": "http://10.8.0.2:8080/mcp",
      "headers": { "Authorization": "Bearer <当前Token>" }
    }
  }
}
```

## 文件传输契约

- 工具覆盖文件信息查询、上传创建、分块写入、上传完成、上传取消、下载打开、分块读取和下载关闭。
- 二进制分块使用 Base64 编码进入 MCP JSON 参数或结果；偏移与长度按原始字节计数。
- 上传按顺序写入目标目录内临时文件，完成时检查总长度及 SHA-256，再发布到目标路径；失败不得留下看似完整的目标文件。
- 覆盖策略按 PRD；提交阶段也检查目标冲突，不能仅在创建上传时检查。
- 平台适配需核实目标替换的原子性；不支持时返回明确错误，不先删除原文件再伪装成原子提交。
- 下载持有受管理的读取句柄并报告大小；检测源文件变化并拒绝宣称校验通过，不承诺对其他进程并发写入提供文件系统快照。
- 文件及分块大小按 PRD 配置；HTTP 请求体上限须容纳 Base64 膨胀及 JSON 元数据，默认 1 MiB。并发传输数默认 8，空闲传输 10 分钟后清理，均可配置。
- 不提供跨服务重启或网络中断后的传输恢复。传输超时后释放句柄并清理临时文件。
- 目录压缩及解压由现有命令能力执行，服务不内置自动解包。
- 本地辅助命令负责本机文件读写、编码和 MCP 调用，服务端仅访问客户机文件系统；详细调用链见下文。

## 命令与后台进程

- 使用启动、读取、状态查询和停止工具；短命令可等待最多 10 秒，超过等待窗口返回进程 ID，后续调用继续读取。
- 参数包括可执行文件、独立参数数组、工作目录、环境变量覆盖和超时。显式使用 shell 时才解释管道及重定向。
- 普通进程保留 stdout/stderr 区分，返回退出码或启动、超时、停止原因。
- 输出按字节游标增量读取，设置有界缓冲；游标已被淘汰时明确返回缺失范围，不静默遗漏日志。
- 执行超时按 PRD；并发进程数默认 16，每个进程合计输出缓冲默认 4 MiB，单次读取最多 64 KiB，均可配置。结束后的状态及日志保留 10 分钟后回收。
- Unix 进程组和 Windows Job Object 等平台机制需验证停止及关闭时对子进程的清理行为。
- 输出按原始字节保存；文本解码需明确编码及非法字节处理，不能将 Windows 非 UTF-8 输出静默损坏。

## 交互式终端

- 工具覆盖创建、输入、读取、调整尺寸、查询和关闭终端会话。
- Linux/macOS 使用 creack/pty v1.1.24；Windows 使用 charmbracelet/x/conpty v0.2.0，系统调用依赖由 Go 模块解析并锁定。不能以普通管道假装交互式终端。
- 会话保留 shell 当前目录及环境；接受终端输入和控制字符。Ctrl+C 作为终端输入交由前台程序处理，不能保证任意程序会退出；强制终止由关闭操作处理。
- 终端输出为合并流，保留 ANSI/VT 控制序列；不宣称终端具有独立 stdout/stderr。
- 断线保留及空闲清理按 PRD；终端输出本身不刷新最后调用时间。默认最多 8 个终端，每个输出缓冲 4 MiB，单次读取最多 64 KiB，均可配置。
- 会话不跨服务重启恢复；正常关闭服务时回收进程、终端句柄和缓冲。
- 不提供图形终端前端或屏幕渲染器；Agent 通过 MCP 输入和读取终端数据。

## 运行与兼容性

- 配置集中校验；错误区分参数错误、权限不足、文件冲突、资源不存在、限额、超时和平台不支持。
- 日志记录工具名、资源 ID、耗时和结果，不默认记录 Token、环境变量值、文件内容或终端输入输出。
- 初版不依赖数据库；进程、终端和传输登记在内存，服务重启后旧 ID 失效。
- 按通用协议基线提供接入示例。除 Go SDK 端到端测试外，增加独立 HTTP/JSON-RPC 协议测试，覆盖初始化、工具发现和调用；不宣称任何未经实际验证的品牌客户端已通过。

## 主要验证边界

- 必须分别验证三种系统的真实 PTY/ConPTY、文件替换、进程树清理和路径处理。
- 交叉编译只能证明构建通过，不能代替 Windows/macOS 的运行验收。
- 当前环境仅确认有 Linux/amd64 的 Go 工具链；其他平台验证环境尚未确认。
- 当前仓库没有业务代码和历史部署，不需要数据迁移；回退通过停止新服务、替换二进制和恢复配置完成。

## 本地辅助命令与数据流

- 同一 Go 模块内提供服务入口及文件传输辅助入口；辅助命令支持 upload 和 download，不在本机再次托管 MCP 服务。
- 接受服务 URL、源路径、目标路径及显式覆盖选项；Token 可选，从环境变量或权限受控文件读取，不要求出现在命令行参数中；未配置时不发送 Authorization，显式无效凭据失败。
- 上传链路：本地流式计算大小及哈希 → 创建 MCP 上传 → 顺序读取本地分块 → MCP 写入 → 校验完成 → 报告结果。扫描与上传期间源文件变化会导致失败，不能报告成功。
- 下载链路：MCP 打开远端文件 → 获取元数据及流式校验信息 → 按偏移读取 → 写本地临时文件 → 校验长度及哈希 → 发布目标。不能向模型输出各块 Base64。
- 进度写 stderr，最终摘要支持结构化 JSON 写 stdout，方便 Agent 判断成功、失败、字节数和校验结果。
- 文件传输只走 MCP，不新增旁路 HTTP 上传下载 API。

## 公共契约与重试

- 应用资源 ID 使用随机值，跨 MCP 协议会话有效；启用鉴权时始终要求 Token，匿名模式下可连接的客户端共享同一信任域。
- 返回结构化字段与简短文本摘要；业务失败通过 MCP 工具错误表达，附稳定错误码。不得仅输出一段无法可靠解析的自然语言错误。
- 输出读取使用绝对字节游标、起始游标、下一游标和截断标记；原始字节可用 Base64 返回，文本视图须明确解码状态。
- 创建进程、终端和上传接受调用方生成的 request_id；同一 ID 与同一参数在保留窗口内返回已有结果，不重复启动。参数不一致则报冲突。
- 辅助命令不盲目重试无法确认是否执行的写入；可以通过资源状态核对后继续当前操作，但不实现用户级断点续传功能。
- 生命周期方法并发安全，关闭可重复调用；读取和停止竞态不得引起死锁、panic 或句柄泄漏。
- 资源终态和幂等记录有过期清理及数量上限；活跃资源上的创建去重记录保留到资源结束，避免长任务重复启动。

## 实施时允许细化的事项

- 模块路径在仓库没有远端地址时使用本地项目名，不虚构 GitHub 组织地址。
- 在不改变 PRD 的前提下，可调整内部目录组织、工具命名与封装方式；如需要改变协议兼容、用户可见默认行为或三平台能力，应重新评审。
- 发布版本依赖在实施时下载核对并写入 go.mod/go.sum；原生系统的进程回收和文件提交验证属于实现及验收步骤，不以文档调研替代。
