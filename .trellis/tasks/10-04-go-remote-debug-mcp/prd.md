# Go 跨操作系统远程调试 MCP 服务

状态：首版已实现；用户随后明确要求 Token 可选，本次调整及验证见 research/optional-token.md。三平台原生验收尚未全部完成。

## 目标与背景

使用 Go 编写部署在客户机上的 MCP 服务，让 AI Agent 在不同操作系统之间完成文件传输、程序运行及交互式调试，减少手工搬运文件和切换终端的工作。

任务创建时仓库只有 Trellis 和开发工具配置；现已包含 Go 服务、辅助命令及后端规范。会话、文档和代码注释使用中文。

## 用户已确认的范围

- 客户机通过内网或 VPN 接受 Agent 直连。
- 支持 Windows、Linux、macOS。
- Token 鉴权可选，操作权限与服务运行账号一致。
- 支持普通命令、后台长进程和交互式终端。
- 支持双向文件传输与大文件分块，目录通过压缩包传输。
- 提供通用 MCP 接入与本地文件传输辅助命令；辅助命令通过 MCP 传输实际字节，避免文件内容占用模型上下文。
- 服务启动时输出可供 Agent 配置的 MCP JSON；本机存在多个可连接 IP 时，分别输出对应配置。

## 功能需求

| 编号 | 需求 |
| --- | --- |
| R1 | 提供可部署的 Go 服务、监听与运行配置、中文使用说明及通用 MCP 接入示例。 |
| R2 | 双向传输文本和二进制文件，支持分块及完整性校验、显式覆盖、取消和失败清理；压缩包按普通文件处理。 |
| R3 | 执行普通命令和后台长进程，支持参数、工作目录、环境变量、超时、增量输出、退出状态和停止。 |
| R4 | 服务及辅助命令支持三种操作系统，按下述兼容范围提供构建和验证流程。 |
| R5 | 未配置或空环境 Token 且未指定凭据文件时允许匿名；配置非空 Token 后每个请求校验；显式凭据文件为空、不可读或非法时失败。客户端可使用服务账号的文件和执行权限，不自动提权。 |
| R6 | 交互式终端支持持续输入、增量输出、会话状态保持、调整尺寸、Ctrl+C 输入和关闭清理。 |
| R7 | 本地辅助命令支持上传及下载，读取或写入本机文件，通过 MCP 与客户机交换分块；失败返回非零退出码，成功报告文件大小和校验结果。 |
| R8 | 成功开始监听后枚举本机 IP，按实际监听范围为每个可连接地址分别输出完整 MCP 配置 JSON，包含传输类型、URL、实际端口，以及启用鉴权时的 Token 配置；匿名时完全省略 headers，便于选择并复制。 |

## 已批准的默认行为

以下默认值已随包含启动配置输出的完整方案获得用户批准。

| 项目 | 首版方案 |
| --- | --- |
| 处理器架构 | 三种系统均提供 amd64、arm64 构建。 |
| 系统边界 | Windows 10 1809+/Windows Server 2019+；macOS 13+；Linux 内核 3.2+ 且具有可用 PTY。运行验收记录实际系统版本，不能把下限说明当成每个版本都已验证。 |
| 客户端兼容 | 支持 Streamable HTTP 和 MCP 2025-11-25 协议协商的通用客户端，启用鉴权时还须支持 Bearer Token；不依赖特定 Agent 品牌。 |
| 文件大小 | 单文件默认上限 4 GiB，每块原始数据最多 256 KiB，均可配置。 |
| 文件覆盖 | 默认拒绝覆盖；显式启用后才允许替换，校验失败不修改原目标。 |
| 普通命令 | 默认执行超时 5 分钟，可配置；后台模式可显式关闭执行超时。 |
| 终端断线 | 网络断开不立即关闭会话；客户端可用会话 ID 再次访问，启用鉴权时须携带同一 Token，无调用活动 30 分钟后清理，可配置。 |
| 服务重启 | 不恢复旧进程、终端或传输会话；正常关闭服务时清理关联资源。 |
| 监听与加密 | 为满足内网多 IP 开箱接入，默认监听 0.0.0.0:8080，可指定单个 IP 或 IPv6 监听地址；支持 TLS 证书配置。 |
| 启动配置输出 | 每个有效地址输出一个独立的 mcpServers JSON，启用鉴权时填入当前 Token，匿名时完全省略 headers；普通运行日志不记录 Token。列出的地址是同一服务的备选入口，选择 Agent 可达的一个使用。 |

## 验收标准

- A1（R1、R4、R5）：在三种操作系统分别启动服务，通过通用 MCP 客户端初始化、发现工具并完成调用；提供六种系统/架构组合的构建检查记录。
- A2（R2、R7）：辅助命令对空文件、文本、二进制和跨多个分块的大文件完成双向传输，两端 SHA-256 一致；额外用超过 256 MiB 的文件验证流式处理，峰值内存不随文件总大小线性增长。
- A3（R2）：错误偏移、非法分块、长度或哈希不一致、超出限额、目标冲突均明确失败；取消和超时清理临时资源，已有目标文件不被失败上传损坏。
- A4（R3）：普通命令返回 stdout、stderr 和退出状态；后台进程运行期间可以继续调用其他工具、读取新增日志并停止包含子进程的任务。
- A5（R6）：三种系统均使用真实终端机制完成多次输入、读取输出、工作目录与环境状态保持、尺寸调整、前台 Ctrl+C 输入和关闭；验证无活动清理及短暂断线后的重新访问。
- A6（R5）：匿名模式能初始化、调用工具和双向传输，辅助命令不发送 Authorization；启用鉴权后缺失或错误 Token 被拒绝；非法显式凭据不得静默退回匿名；所有调用仍受系统账号权限约束；非法 Origin、资源限额和并发错误具有明确结果，不泄露 Token。
- A7（R2、R3、R4、R6、R7）：完成本机上传程序或脚本、客户机执行或交互调试、读取输出、下载产物的完整流程，并记录两端系统。
- A8（R1、R4）：中文文档涵盖部署、鉴权、辅助命令、终端操作、默认值及限制；明确区分实际运行通过、构建通过和未验证的平台。
- A9（R8）：模拟多网卡、同网卡多个 IP、重复地址、停用接口和 IPv4/IPv6 环境，验证按监听范围过滤、去重、稳定排序，且每段输出 JSON 均可解析并包含正确 URL 与当前模式的配置（匿名无 headers，启用鉴权时含 Authorization）。
- A10（R8）：监听失败不输出成功配置；动态端口使用实际绑定端口；启用 TLS 使用 https；单 IP 绑定仅输出对应地址，IPv6 URL 使用方括号。启动 JSON 可含当前 Token，普通运行日志及错误输出不泄露 Token。

## 首版不包含

- 公网接入方案、客户机反向中转、多客户机管理平台或管理前端。
- 目录递归同步、断点续传和自动压缩解包；目录可使用已有命令打包后传输。
- 多租户、目录沙箱、命令白名单和自动提权。工作目录不构成权限隔离。
- 图形桌面、终端屏幕渲染器、专用断点调试协议、服务自动升级或系统服务自动安装器。
- 服务重启后恢复会话，以及专为只支持旧式 SSE、stdio 或 OAuth 自动发现的客户端提供适配。

## 约束与延期项

- 当前仅确认 Linux/amd64 开发环境。三平台运行验收仍是交付要求；缺少验证环境时记录未完成项，不得以交叉编译代替。
- PTY/ConPTY、文件提交和子进程清理的差异必须实际验证；若实现需要改变上述能力或兼容范围，应先修订方案。
- 通用接入意味着协议级兼容和配置示例，不代表已测试所有 Agent 产品。本地辅助命令需要 Agent 具有本机命令执行能力。
- 启动 JSON 采用常见的 mcpServers/type/url/headers 格式，并不表示所有客户端使用相同配置文件格式。网卡地址枚举不能证明 Agent 侧路由、防火墙或 TLS 证书信任已就绪。
- 依赖、协议、数据契约及实施顺序分别记录于 design.md、research/transport-terminal.md 和 implement.md。
