## 实施顺序

1. 加载后端及跨层规范；确定 Go 模块路径、锁定所选依赖，建立程序入口、配置校验和测试基础。
2. 接入官方 MCP SDK、HTTP 传输、鉴权、Origin 校验、请求限额及正常关闭逻辑；实现按实际监听范围枚举 IP、生成启动配置 JSON 和普通日志脱敏。
3. 实现上传下载状态机、分块边界、校验、文件冲突和临时文件清理。
4. 实现普通命令及后台进程、增量输出、状态读取、超时和进程树清理。
5. 实现统一终端契约及 Unix PTY、Windows ConPTY 适配，并验证输入、输出、尺寸和关闭。
6. 实现本地文件上传下载辅助命令，接入通用 MCP 客户端，完成大文件和交互终端端到端流程及独立协议验证。

8. 调度 Trellis 检查代理执行最终质量检查；把已验证的项目规范写回后端 spec。

各步由 Trellis 实施代理执行，主会话协调需求及接口；代码阶段按模块明确所有权，共用文件串行修改。子代理上下文包含真实研究与规范条目。

## 验证计划

- 格式：对 Go 文件运行 gofmt，并检查无格式差异。
- 静态检查：go vet ./...。
- 单元与集成测试：go test ./...；支持的平台执行 go test -race ./...。
- 按 Windows/Linux/macOS × amd64/arm64 六组合构建，输出到独立构建目录；服务与辅助命令都需检查。
- 使用 MCP 客户端完成初始化、工具发现、合法调用、无效 Token、非法 Origin 和资源限额验证；独立 HTTP/JSON-RPC 测试覆盖协议基线，避免仅用相同 SDK 掩盖兼容性错误。
- 启动配置采用可注入的网卡枚举数据验证多 IP、过滤、去重、稳定顺序、IPv6 URL、Token JSON 转义和独立对象解析；用真实监听器验证动态端口、绑定失败以及配置 URL 实际可连接。
- 核对启动配置输出包含当前 Token，而普通日志和错误信息没有 Token；演示与测试仅使用虚构 Token，不把运行环境的真实凭据写进文件。
- 文件测试覆盖空文件、二进制、多块、校验失败、错误偏移、目标冲突、显式覆盖和取消清理；使用超过 256 MiB 的文件核对流式内存占用。
- 进程测试覆盖不同退出码、交替 stdout/stderr、大量输出、超时和含子进程的停止。
- 终端测试覆盖多次输入、会话状态保持、尺寸变化、前台 Ctrl+C、关闭和重连；创建类操作另验证 request_id 去重及冲突。
- 在三种操作系统实际执行运行测试；缺少环境时保留未通过的验收项，明确报告，不能将交叉编译当成运行通过。
- 目标客户端的文件传输须由程序处理实际本地字节，校验两端哈希，验证不依赖模型复述二进制内容。

## 风险与回退点

- Windows 终端创建、关闭和进程树终止优先做可执行验证，失败时修订设计，不能静默削减三平台交互终端需求。
- 文件提交保留旧文件直到新文件校验完成，避免中途失败破坏目标。
- 启动、停止与输出读取存在并发路径，重点检查死锁、数据竞争及句柄泄漏。
- 仓库现有 Trellis 和平台初始化文件为未提交内容；实施时保留，提交前按范围核对。
