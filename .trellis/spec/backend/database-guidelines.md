# 状态存储与资源管理

本项目当前没有数据库。`transfer.Manager` 和 `execution.Manager` 使用内存登记活跃资源、幂等请求及保留期内的终态。

应用资源 ID 不绑定到单次 HTTP 请求或 MCP 协议会话；使用相同 Token 的调用方属于同一信任域。ID 本身不替代鉴权。服务重启后旧 ID 失效，不能宣称持久恢复。

每类资源必须同时考虑活跃数量、终态记录数量、内存缓冲和过期清理。创建去重记录不能在活跃进程仍运行时被驱逐，避免请求重试启动重复程序。

文件只使用临时文件和目标文件持久存储；成功发布、取消、超时及关闭均要检查临时名称清理。大文件哈希流式执行，并避免长期占用全局管理锁阻塞其他操作或关闭。

正常服务退出先停止接入，再关闭进程、终端、传输及协议会话。Unix 组回收和 Windows Job Object 有各自实现，不能只关闭 MCP 连接就宣称进程已停止。
